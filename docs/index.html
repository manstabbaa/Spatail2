Content spec

Ten elements, eight ways to anchor them

A planner never draws anything. It returns a plan: operations on builds, each a named group of elements anchored to entities in the room. The same JSON comes from the on-device planner, the AI service and the session link, and it is what both apps render.

The two apps

One runtime, a headset app and a dev tool

Both apps are thin shells around the shared package com.spatail.core. Each supplies four things: the camera, what the device knows about the room, a pointer, and text or speech input. Press Play in either Unity project without a device and you get the same runtime in a simulated room.

AI planner

A small service between the device and Claude

Devices never hold a model API key. They send the request, the room model, the site's knowledge and the current builds to the planner service; it calls Claude with a schema-constrained output and returns a plan in the wire format above.

Run it

Then set the planner URL to this machine's LAN address, for example http://192.168.1.20:8787: in the iOS dev tool under Settings, on the headset by pushing settings from the dev tool over the session link, or at build time with Assets/Resources/SpatailConfig.json.

What one call looks like

  • The standing instructions and the site's knowledge go in two cached system blocks, so repeat requests for a site read most of their input from the prompt cache.
  • The room, the current builds, what the user is pointing at and what they said go in the user message.
  • The response is constrained to the plan schema with structured outputs, so the model cannot return something the device cannot parse.
  • If the model declines a request, the API retries on its default fallback model within the same call.
  • Failures come back as a plan with error set. The device shows the reply and answers with its on-device planner instead.
Extend

New equipment, new content, new planners

The pump station is data. The equipment, its parts, its stand-in hologram and everything known about it live in one JSON file; nothing about pumps is in the code.

Anatomy of a site

Select a part to see its definition and find it in the simulator.

Register new equipment

Copy pump_station.json, describe your parts (id, label, aliases, bounds, optional stand-in shapes) and your knowledge (procedures, flows, faults, metrics, spares, people). Point SpatailApp.DefaultSite at it. Fixtures can bind to real furniture: a "mount": "table" fixture adopts a real table when the room has one and falls back to a hologram when it does not.

Add an element type

Add the name to ElementType and its fields to Element and SpecJson, write an ElementView subclass and register it in ContentRenderer.AddView, then add it to the service schema and system prompt. The service tests fail until the C# and TypeScript lists match.

Write a planner

Implement IPlanner.PlanAsync(PlanRequest) and return a PlanResult. BuildFactory shows what well-formed builds look like. Whatever a planner returns goes through SpecJson.Sanitize, which drops elements anchored to things that are not in the room.
